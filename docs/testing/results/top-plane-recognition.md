## Diagnosis and supported boundary

The owner reported authenticated Windows Onshape: the extension and panel load, a Part Studio is active, Default geometry contains **Top**, **Front**, and **Right**, Sketch 2 is active, the dialog displays **Sketch plane: Top plane**, the viewport displays **Top**, and Step 2 Show me returns **MISSING**. The accompanying diagnostic reported `scannedElements: 5000`, `scanLimitReached: true`, no candidates, and Top/Front/Right as MISSING. That diagnostic result only covered an incomplete prefix of its scan; it does not establish that the feature tree had no matching elements. Production Show me follows a different candidate-query path, so the two outcomes were not interchangeable. The live Show me failure is confirmed; the exact matching failure is not.

Confirmed offline defects in the reviewed code, reproduced by controlled regressions:

- Bare Top/Front/Right labels cannot be safely identified with the former long-label matcher alone.
- A hidden stronger match suppresses a visible supported weaker match.
- Nested labels and interactive descendants can describe one row, rather than independent controls.
- An overlay can remain on a recycled, still-visible node whose semantic identity changed.
- Hosted CI exposed a production SPA integration defect: WXT dispatches its Navigation API location-change event before `location.href` commits. Synchronous mounting reads the old document and ignores the destination. The listener now clears immediately and defers reading the committed route to a microtask. The production regression also requires a fresh lesson context after navigation.
- Panel Show me can falsely describe success when no callback reports a mounted highlight; stale highlights survive some lesson transitions.

The label mismatch is a plausible contributor to the live failure. Missing semantics, unsupported nesting, or a different actionable element remain hypotheses. No production Onshape-specific selector or generated class was added. The ARIA structures in tests are controlled contracts, **not captured real Onshape DOM**. If Onshape does not expose these relationships, recognition deliberately rejects the row; the owner diagnostic is needed before a narrowly justified adapter can be added.

## Owner: shortest no-DevTools procedure

1. Download the **Top-plane diagnostic build** artifact linked in PR #1. Extract the outer artifact ZIP, then extract the Chrome inner ZIP. Follow [Load unpacked](../live-setup.md) using the folder with `manifest.json` directly inside. Remove/disable an older Leqad copy first; refresh the Onshape page after updating.
2. In an authorized disposable Part Studio, expand Default geometry before sketch editing. On lesson Step 2 click **Show me**. Check that the actual Top row is framed, its label remains readable, and clicking the row works. A camera/canvas/dialog highlight is a FAIL. Highlighting alone must leave the step **Visited**.
3. Start Sketch manually. Return to Step 2 if needed and click Show me. Record whether supported editing controls produce “already editing a sketch” guidance and the actual visible dialog observation. Use **I've finished this step** if appropriate; **Marked done** is self-reported, not verified CAD.
4. If recognition fails, choose **Enable recognition diagnostics → Capture Top row**. Within 20 seconds, click the visible Top entry once. The listener does not cancel or alter that click. It ignores clicks inside Leqad and removes itself after the first page click or timeout.
5. Choose **Copy recognition diagnostics**. The JSON combines a bounded semantic-tree scan with the captured element and up to ten ancestors. It reports allowed tag/role values, whether accessible attributes exist, whether names match Top/Front/Right/Default geometry, actionability, context and visibility codes. It contains no raw page text or attribute values. If clipboard access is unavailable, select/copy the displayed **Recognition diagnostics output** text.
6. Choose **Turn off recognition diagnostics** to clear the report and cancel any active listener. The scan does not run production Show me recognition; use Show me's visible outcome separately. Do not send passwords, cookies, tokens, document links/IDs, private geometry, account information, full HTML, or unredacted screenshots.

Diagnostic names are a bounded subset, not a complete browser accessibility computation. The region scan starts at exposed tree/treegrid landmarks; it does not traverse the whole document or infer that the clicked structure is valid. An absent tree landmark is reported as `NO_SEMANTIC_TREE_ROOT`; an exhausted tree scan is `INCOMPLETE`, never `MISSING`. A captured `NO_ARIA_NAME_ATTRIBUTE_ON_TOP_LABEL_OR_ROW` finding means only that those attributes are absent from the captured label and resolved row; visible text or a title may still provide an accessible name. Production recognition is explicitly `NOT_RUN` in this diagnostic report. Captured structure provides evidence for a later adapter; it does not change production recognition.
