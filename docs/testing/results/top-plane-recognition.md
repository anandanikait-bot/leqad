## Diagnosis and supported boundary

The owner reported authenticated Windows Onshape: Default geometry is expanded and Top, Front, and Right are visible, but Show me does not identify the Top row. The earlier diagnostic scanned 5,000 elements and hit its limit; that incomplete scan did not establish that the feature tree had no matching elements. The newly supplied authenticated DOM capture observes a visible exact `Top` span and multiple `div` ancestors whose bounded names also match `Top`. It found no document `tree`/`treegrid` role and no captured ancestor with a recognized tree row, button role, or actionable markup signal. It did not capture any ancestor named Default geometry. Its `productionRecognition` value is `NOT_RUN`; this report does not infer a production Show me status from that diagnostic.

Code review explains the mismatch: `referencePlaneContext()` accepts a feature-tree context only below `role=tree`/`treegrid` and a named Default geometry semantic group; `referencePlaneCandidate()` then requires a recognized actionable row whose own name matches the requested plane. The supplied capture lacks those signals, and the candidate is rejected as the owner reported. A `div` can still handle a click through JavaScript, so the absent markup signals do not prove it is inert. The supplied capture has no sibling relationships or element geometry, so it cannot establish which `div` is a row, whether Default geometry is a parent or sibling, or where a correct frame should end. This sprint extends only the opt-in diagnostic to collect those bounded relationships. It does not change production recognition or verification.

Confirmed offline defects in the reviewed code, reproduced by controlled regressions:

- Bare Top/Front/Right labels cannot be safely identified with the former long-label matcher alone.
- A hidden stronger match suppresses a visible supported weaker match.
- Nested labels and interactive descendants can describe one row, rather than independent controls.
- An overlay can remain on a recycled, still-visible node whose semantic identity changed.
- Hosted CI exposed a production SPA integration defect: WXT dispatches its Navigation API location-change event before `location.href` commits. Synchronous mounting reads the old document and ignores the destination. The listener now clears immediately and defers reading the committed route to a microtask. The production regression also requires a fresh lesson context after navigation.
- Panel Show me can falsely describe success when no callback reports a mounted highlight; stale highlights survive some lesson transitions.

The ARIA tree, named group, and markup-actionable row assumptions are incompatible with the supplied capture. The missing sibling outline means the actual feature-list relationship and row boundary remain unestablished. No production Onshape-specific selector or generated class was added. Test DOMs are simulations unless explicitly labeled otherwise; none asserts that its structure is the actual Onshape DOM. A reusable non-ARIA adapter and production highlighting fix remain pending this short structural capture.

## Owner: shortest no-DevTools procedure

1. Download the **Top-plane diagnostic build** artifact linked in PR #1. Extract the outer artifact ZIP, then extract the Chrome inner ZIP. Follow [Load unpacked](../live-setup.md) using the folder with `manifest.json` directly inside. Remove or disable an older Leqad copy first, then refresh Onshape.
2. In an authorized disposable Part Studio, expand Default geometry so Top, Front, and Right are visible. In Leqad choose **Enable recognition diagnostics → Capture Top row**. Within 20 seconds, click the visible Top entry once. The one-shot listener does not cancel or alter the click, ignores Leqad clicks, and removes itself after the first page click or timeout.
3. Choose **Copy recognition diagnostics** and send the JSON report. Version 3 contains the bounded semantic-tree scan, the clicked path, parent/sibling relationships, relative geometry ratios, exact matches for Top/Front/Right/Default geometry, and sanitized visibility/context/markup-actionability signals. It omits arbitrary page text and attribute values. `JAVASCRIPT_HANDLER_NOT_INSPECTED` means the capture cannot establish whether a nonsemantic `div` handles clicks. If clipboard access is unavailable, copy the displayed **Recognition diagnostics output** text.
4. If the report says the sibling outline is truncated, also note whether Default geometry and all three plane entries are visibly adjacent in the feature list; do not send a screenshot unless it has been sanitized first. Choose **Turn off recognition diagnostics** to clear the report. Do not send passwords, cookies, tokens, document links/IDs, private geometry, account information, full HTML, or unredacted screenshots.

Diagnostic names are a bounded subset, not a complete browser accessibility computation. The region scan starts at exposed tree/treegrid landmarks; it does not traverse the whole document or infer that the clicked structure is valid. The sibling outline inspects at most eight ancestors, five sibling elements per ancestor, and 256 elements in total. Sibling counts are capped; omitted siblings and truncated walks are marked. Relative geometry is measured against the clicked label, rounded to tenths, and excludes absolute screen coordinates. An absent tree landmark is `NO_SEMANTIC_TREE_ROOT`; an exhausted semantic-tree scan is `INCOMPLETE`, never a production `MISSING`. Production recognition is explicitly `NOT_RUN`. The captured outline is evidence for a later adapter; it does not change production recognition.
